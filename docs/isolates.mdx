# Isolates

Each Dart isolate opens and owns its own `NativeSession`. Construct a generated
API from that session inside the isolate, and close the session before the
isolate exits. Send ordinary Dart values between isolates; native handles and
session pointers belong to the isolate that created them.

```dart
import 'dart:isolate';

Future<int> calculate() async {
  final session = createSession();
  try {
    return await ZigApi(session).add((a: 20, b: 22));
  } finally {
    await session.close();
  }
}

final results = await Future.wait([
  Isolate.run(calculate),
  Isolate.run(calculate),
]);
```

The [isolates example](https://github.com/kingwill101/dart_zig/tree/main/example/isolates_example)
runs this pattern as a standalone Dart program. Each session has its own
pending calls, callback registrations, state snapshots, and native handles.
Do not carry a `SignalPack` or borrowed native buffer across isolate boundaries;
copy the needed Dart data first.

If one isolate should coordinate all native work, keep the session there and
send application messages to that isolate. If isolates perform independent
native work, give each one a session as above. The core package does not
mandate either application architecture.
