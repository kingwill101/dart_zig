# Errors and diagnostics

Await generated calls and handle their failures. Transport and application
failures are reported as `NativeException`; invalid Dart arguments can throw
`ArgumentError`, and malformed codec input can throw `FormatException`.
Native side effects may already have occurred before a call fails.

## Handle failures by code

Common failure codes include:

| Code | Meaning |
| --- | --- |
| `busy` | Pending-call count or payload budget is exhausted |
| `too_large` | Payload exceeds the configured session limit |
| `cancelled`, `deadline`, `closed` | Cancellation, timeout, or shutdown |
| `native_N` | Application or runtime failure frame |
| `signal_overflow` | A signal listener exceeded its queued-message or byte budget |

The message text is diagnostic detail, not a stable error identifier. A
one-way signal has no call future carrying its handler's result.

## Observe signal failures

Observe `session.signalErrors` or the generated endpoint's `errors` stream
for native signal failures. Endpoint `errors` also reports decoding failures.
These streams deliver error objects as data events; subscribe with `listen`.
Handle errors on the endpoint's message `stream` as well: subscriber overflow
is delivered there as a stream error. Native failure-frame delivery is best
effort when output capacity is full.

## Logs and runtime counters

Pass `onDiagnostic` when creating a session to observe lifecycle and
backpressure events. `session.stats` reports queue and transport counters.
`forwardNativeLogs(session, sink)` forwards structured Zig logs to your host
logger and registers its own cleanup:

```dart
await initializeZig();
final session = createSession(
  onDiagnostic: (event) => print('${event.kind}: route ${event.route}'),
);
try {
  forwardNativeLogs(session, (log) => print('[${log.scope}] ${log.message}'));
  // Run your generated API here.
} finally {
  await session.close();
}
```

Use the [diagnostics example](https://github.com/kingwill101/dart_zig/tree/main/example/diagnostics_example)
to see a native log reach Dart. For queue limits and shutdown behavior, read
[buffers and ownership](/buffers-and-ownership) and
[cleanup and restart](/cleanup-and-restart).
