# Dart and Zig, working together

Write your handlers in Zig and call them through generated Dart methods.
`dart_zig` connects the two with typed calls, streams, signals, callbacks,
and explicit resource ownership. Sessions manage communication and cleanup
for related work.

Your application owns its Zig source. A Dart build hook compiles it into a
native library; Web applications load a WebAssembly module. The core package
has no Flutter dependency and does not prescribe an application protocol.

## Start with your use case

Read [why dart_zig?](/why-dart-zig) for a comparison with direct generated FFI
bindings, including how the native runtime uses Dart's C API.

For asynchronous work, native workers, or Web/Wasm, follow
[getting started](/getting-started) to generate and run your first call.
For a short synchronous native function, [direct FFI](/direct-ffi) uses
`native_toolchain_zig` without a session or message codec.

The package is under active development and is not published to pub.dev.
The setup guide uses a local checkout and the repository's build-tooling fork.

## Integrate with your application

Use the guides for [Dart and Flutter](/dart-and-flutter),
[Web and Wasm](/web-and-wasm), or [Dart isolates](/isolates).
The API is shared across native and Web targets, but their execution and
integer limits differ.

Read [cleanup and restart](/cleanup-and-restart) when deciding who owns a
session, and [errors and diagnostics](/errors-and-diagnostics) for failures,
logs, and queue pressure. The [examples](/examples) provide runnable projects
for each feature.
