# Signals and state

Signals deliver live messages. State endpoints retain the latest received
value for new subscribers; they do not retain a history of every update.

## Declare your endpoints

Declare a named endpoint in `pub const events` with a `.signal` or `.state`
kind. The generator creates a `SignalEndpoint<T>` on `ZigApi` for each name.

```zig
const dz = @import("dart_zig");

pub const events = .{
    .notifications = .{
        .kind = dz.protocol.RouteKind.signal,
        .message = dz.protocol.Text,
    },
    .updates = .{
        .kind = dz.protocol.RouteKind.state,
        .message = dz.protocol.Text,
    },
};

pub fn publish(context: *dz.Context, message: dz.protocol.Text) !void {
    try dz.events.emit(context, events, .notifications, message, &.{});
}
```

## Receive a signal

Construct `ZigApi(session)` before state updates you need to replay. Its
endpoints subscribe to the session immediately, even if the corresponding
field is read later. Subscribe before emitting a non-replaying signal:

```dart
final api = ZigApi(session);
final next = api.notifications.stream.first;
await api.publish('hello');
final pack = await next;
try {
  print(pack.message);
} finally {
  pack.dispose();
}
```

## Read the latest state

`api.updates.stream` receives later state values, and a new subscriber receives
the current snapshot if one exists. `api.updates.latest` returns `null` before
an update arrives; otherwise it returns a retained pack that must be disposed:

```dart
final snapshot = api.updates.latest;
if (snapshot != null) {
  try {
    print(snapshot.message);
  } finally {
    snapshot.dispose();
  }
}
```

The snapshot belongs to that endpoint instance in Dart, not a persistent native
store. Reuse your `ZigApi` instance. Recreating it cannot recover updates received
before its endpoints subscribed. Closing the endpoint or session clears its cache.

## Send from Dart

An endpoint's `send(message)` sends Dart-to-Zig input. Its future completes
when the message enters the queue, not when application logic has processed it.
For events declared in `handlers.zig`, the generated Zig dispatcher validates
and relays incoming messages back to the endpoint's listeners. For example,
`await api.updates.send('ready')` sends a state update through that route.
Use a [call](/calls) when native application logic must process a request and
return a result or acknowledgment.

## Delivery and ownership

Pausing a signal subscription does not pause its producer. Generated signal
endpoints default to 64 queued messages and 1 MiB per listener; exceeding the
budget reports `signal_overflow` on that listener and closes it. State endpoints
keep only the latest pending update, so intermediate values can be skipped.
Use a [stream](/streams) when the consumer must pace production.

Each `SignalPack` owns an attachment lease, including when the attachment is
empty. Read [buffers and ownership](/buffers-and-ownership) before retaining one.
A Flutter [StreamBuilder example](/dart-and-flutter) shows a typed Zig message
on screen.
